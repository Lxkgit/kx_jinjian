# 组织树接口改造技术设计文档

## 1. 文档信息

- 项目：`kx_jinjian`
- 设计范围：组织树查询、ES 手动全量同步，以及四个基础组织管理接口的数据字段适配。
- 关联控制器：`SysDeptController`，现有路径前缀为 `/dept`。
- 设计原则：沿用项目现有 `AjaxResult` 响应封装、组织关系字段和 `@DataScope` 数据权限机制；本设计不包含前端改造。
- 状态：技术设计稿；实施前需核对当前 ES 版本、依赖、数据库表结构和现有权限配置。

## 2. 范围与边界

### 2.1 本次范围

1. 新增 `GET /dept/tree`：组织树懒加载和机构名称搜索。
2. 新增 `POST /dept/es/sync`：手动全量同步数据库组织数据至 ES。
3. 仅调整以下四个现有基础组织管理接口，使新增字段能够正常查询、保存和更新：
   - `GET /dept/list`
   - `POST /dept`
   - `PUT /dept`
   - `DELETE /dept/{deptId}`
4. 沿用现有 `@DataScope` 与现有操作级权限校验。

### 2.2 明确不在范围内

- 不改造 `/dept/list/exclude/{deptId}`、`/dept/selectDeptTree`、`/dept/pilotCenterPart/networkList`、`/dept/grid/org` 等其他现有接口。
- 不修改前端，不新增 `hasChildren` 等子节点标识字段。
- 不自行推断或补齐第三方提供的 `org_type`、`org_introduction`、`parent_org_num` 历史数据。
- 经纬度由第三方提供；坐标缺失和网格落格不属于本次业务改造，不实现坐标推算或网格编码推断。
- 不使用 `org_num`、`parent_org_num` 推导组织父子关系。

## 3. 组织关系与字段模型

### 3.1 组织关系

组织树固定以“浙江省”为根节点。层级关系使用数据库现有字段：

- `dept_id`：组织主键。
- `parent_id`：直接父组织 ID。
- `ancestors`：数据库现有祖级路径字符串。

ES 中额外维护派生字段 `ancestor_ids`（数值数组），由 `ancestors` 解析得到，用于祖先节点检索；该字段不是新的业务主数据，不回写数据库。

监管机构、银行机构均按数据库实际维护的父子关系展示，不根据机构类型或第三方机构编号重建层级。

### 3.2 节点字段

组织树节点沿用项目常见的 Java Bean JSON 驼峰命名，返回以下字段：

| JSON 字段 | 来源 | 说明 |
|---|---|---|
| `deptId` | `dept_id` | 内部组织 ID |
| `parentId` | `parent_id` | 直接父组织 ID |
| `ancestors` | `ancestors` | 原始祖级路径 |
| `deptName` | `dept_name` | 机构名称 |
| `orgNum` | `org_num` | 本机构第三方机构编号 |
| `parentOrgNum` | `parent_org_num` | 上级第三方机构编号 |
| `address` | `address` | 机构地址 |
| `dutyName` | `duty_name` | 负责人姓名 |
| `dutyTelephone` | `duty_telephone` | 负责人固定电话 |
| `dutyPhone` | `duty_phone` | 负责人移动电话 |
| `lng` | 数据库已有字段（如存在） | 经度；当前缺失时返回 `null` |
| `lat` | 数据库已有字段（如存在） | 纬度；当前缺失时返回 `null` |
| `orgType` | `org_type` | 机构类型：省/市/区/总/分/支 |
| `orgIntroduction` | `org_introduction` | 机构介绍 |

`lng`、`lat` 若当前表结构不存在，不在本次擅自新增字段；接口 DTO 可将其作为可空字段输出，待第三方数据和后续字段方案明确后再接入。所属网格字段本次不计算、不假造编码。

### 3.3 新增数据库字段

实施前先检查 `sys_dept` 是否已有同名字段。不存在时再执行对应迁移：

```sql
ALTER TABLE `sys_dept`
    ADD COLUMN `org_type` varchar(20) DEFAULT NULL COMMENT '机构类型：省/市/区/总/分/支',
    ADD COLUMN `org_introduction` text COMMENT '机构介绍',
    ADD COLUMN `parent_org_num` varchar(100) DEFAULT NULL COMMENT '上级机构第三方机构编号';
```

此 SQL 是设计示例，不应未经表结构核对直接重复执行。Java 实体、Mapper 查询列、Mapper 新增/更新 SQL 和 ES 同步字段需同步适配。

## 4. 接口一：组织树查询

### 4.1 基本信息

- URL：`GET /dept/tree`
- 参数：`parentId`、`keyword`，均可选。
- 响应：沿用项目 `AjaxResult`，即 `code`、`msg`、`data`。
- `data`：组织节点数组；每个节点返回第 3.2 节约定字段。
- 不新增子节点标识字段，不要求前端改造。

### 4.2 参数规则

| 参数 | 类型 | 规则 |
|---|---|---|
| `parentId` | Long | 未传且未传有效 `keyword` 时返回浙江省根节点；传入时查询该节点的直接下级 |
| `keyword` | String | 去除首尾空白后判空；非空时按机构名称搜索，搜索模式忽略 `parentId` |

两种查询模式互斥：非空 `keyword` 优先进入搜索模式；否则进入懒加载模式。

### 4.3 懒加载流程

1. 首次调用无参数，定位数据库中作为根节点的“浙江省”组织记录并返回根节点本身，不一次性返回整棵树。
2. 展开节点时，前端传该节点 `deptId` 作为 `parentId`。
3. 服务端通过 ES 精确查询 `parent_id = parentId`，仅返回直接下级节点。
4. 子节点排序沿用项目现有组织排序规则；若现有规则无法直接复用，按 `orderNum` 升序、`dept_id` 升序作为稳定兜底。
5. 无下级节点时返回成功响应和空数组 `data: []`。

### 4.4 名称搜索流程

1. 对 `keyword` 去除首尾空白；空白关键字按普通根节点/懒加载规则处理，不发起全量模糊搜索。
2. 在 ES 中搜索 `dept_name`，使用适合中文机构名称的匹配方式。默认采用名称包含/分词匹配；不将用户输入直接拼接成查询 DSL。
3. 返回命中的机构记录。
4. 根据命中记录中的 `ancestor_ids` 查找所有上级记录，按从根到命中机构的顺序组合结果。
5. 不返回命中机构的下级节点。
6. 同一条上级路径中的重复祖先去重；多个命中结果共享祖先时，响应中按 `deptId` 去重，并保持根到叶的稳定顺序。若产品后续要求以树形嵌套 JSON 表示，可另行定义；本次约定 `data` 为平铺节点数组，避免与现有 AjaxResult 风格冲突。

### 4.5 响应示例

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": [
    {
      "deptId": 100,
      "parentId": 0,
      "ancestors": "0",
      "deptName": "浙江省",
      "orgNum": null,
      "parentOrgNum": null,
      "address": null,
      "dutyName": null,
      "dutyTelephone": null,
      "dutyPhone": null,
      "lng": null,
      "lat": null,
      "orgType": null,
      "orgIntroduction": null
    }
  ]
}
```

以上 ID、父级关系和根节点实际记录均以数据库为准，示例仅说明 JSON 结构。

## 5. 数据权限设计

### 5.1 必须遵守的规则

组织树查询复用现有 `@DataScope` 规则；新增、修改、删除仍保留现有 `checkDeptDataScope` 等操作级校验。不能因为新增注解而移除原有校验。

### 5.2 ES 查询与 DataScope 的衔接

当前 `DataScopeAspect` 的核心行为是生成 SQL 条件并写入 `BaseEntity.params.dataScope`。ES 查询不会自动执行这段 SQL，因此**仅在 ES 查询方法上添加 `@DataScope` 不足以实现权限隔离**。

建议采用以下衔接方式：

1. 在数据库 Mapper 中增加专用的“当前用户可见组织 ID 查询”，使用 `@DataScope` 注解，并确保对应 SQL 真正引用 `params.dataScope`。
2. 取得当前账号可见的组织 ID 集合，作为 ES 查询过滤条件；懒加载、名称搜索和祖先路径还原均应用同一权限集合。
3. 固定根节点“浙江省”作为路径锚点。除根节点的必要展示字段外，不应因为还原路径而返回权限范围外组织的完整敏感信息。
4. 如果用户可见 ID 数量较大，需评估 terms 查询大小限制；必要时采用分批过滤或在数据库侧完成权限范围裁剪后再查询 ES。不能为了性能移除数据权限过滤。
5. 同步接口读取全量组织数据，不能用当前登录人的 `@DataScope` 限制同步范围；应通过独立的管理员操作权限限制调用者。

实施前需检查项目现有数据权限规则对“本部门及下级”“仅本人”等范围的实际含义，并据此实现可见 ID 查询，确保和既有 SQL 结果一致。

## 6. ES 索引设计

### 6.1 索引名称

- 物理索引初始名称：`sys_dept_org_v1`
- 业务查询别名：`sys_dept_org`
- 以后需要变更不可兼容 mapping 时，创建新版本物理索引（如 `sys_dept_org_v2`），再切换别名。
- 所有业务查询使用别名，不将物理索引名硬编码在查询业务逻辑中。

### 6.2 文档唯一标识

使用数据库 `dept_id` 作为 ES 文档 `_id`。一次同步中，同一组织只能对应一份文档；删除数据库记录的组织会在全量新索引中自然消失。

### 6.3 字段映射建议

| 字段 | ES 类型 | 用途 |
|---|---|---|
| `dept_id` | `long` | 内部 ID，且作为 `_id` |
| `parent_id` | `long` | 查询直接下级 |
| `ancestors` | `keyword` | 保留数据库原始祖级字符串 |
| `ancestor_ids` | `long` 数组 | 从祖级字符串解析出的祖先 ID，便于检索 |
| `dept_name` | `text`，含 `keyword` 子字段 | 机构名称匹配和精确排序 |
| `org_num` | `keyword` | 第三方机构编号 |
| `parent_org_num` | `keyword` | 上级第三方机构编号 |
| `address` | `text`，含 `keyword` 子字段（按需） | 地址展示/检索 |
| `duty_name`、`duty_telephone`、`duty_phone` | `keyword` | 负责人及联系方式 |
| `org_type` | `keyword` | 机构类型筛选 |
| `org_introduction` | `text` | 机构介绍 |
| `lng`、`lat` | `double` | 预留坐标字段；缺失时不参与落格计算 |
| `order_num` | `integer` | 组织节点排序（若数据库字段存在） |
| `status`、`del_flag` | 按数据库字段类型映射 | 依据项目现有状态/删除规则过滤 |

ES mapping 需使用项目实际部署版本支持的语法。对 `dept_name` 的中文搜索，需根据当前 ES 分词器情况选择已安装的中文 analyzer；若未安装专用中文分词器，先采用兼容的基础匹配方案，不将未安装插件作为部署前提。

### 6.4 查询 DSL 逻辑

- 直接子节点：`term(parent_id = parentId)`，并按 `order_num`、`dept_id` 排序。
- 机构名称搜索：对 `dept_name` 使用 `match` 或 `wildcard` 策略；不得在未评估数据量前使用低选择性前后通配符造成全索引扫描。
- 祖先检索：根据 `ancestor_ids` 中的 ID 查询对应文档；根据 `ancestor_ids` 的顺序或原始 `ancestors` 解析顺序还原路径。
- 所有查询都应排除数据库规则中不可用或已删除的组织；状态字段的具体判定以当前项目实现为准。
- ES 不负责推断组织层级，`org_num` 与 `parent_org_num` 只做展示和第三方对接。

## 7. 接口二：手动全量同步 ES

### 7.1 基本信息

- URL：`POST /dept/es/sync`
- 请求参数：无。
- 响应：沿用 `AjaxResult`。
- 权限：必须配置为受限的管理员操作权限。建议权限标识使用独立的组织同步权限，并在实施时与项目现有权限菜单/授权配置保持一致；不可仅依赖隐藏按钮。

### 7.2 全量覆盖策略

采用“新建物理索引 -> 全量写入 -> 校验 -> 原子切换别名”的方式，不在当前线上索引上直接清空后重灌。

1. 获取同步互斥锁，防止多个全量任务同时运行。
2. 从数据库读取全部应同步组织记录，按批次构建文档。
3. 创建本次全量同步的临时物理索引；mapping 必须先显式创建。
4. 以 `dept_id` 作为 `_id` 批量写入，使用 Bulk API 并检查每条 bulk item 的失败状态。
5. 等待 ES refresh，并校验写入文档总数与本次应同步总数一致；同时校验根节点记录存在、关键关系字段可用。
6. 校验通过后，通过一次原子 `_aliases` 操作，将 `sys_dept_org` 从旧物理索引切换到新物理索引。
7. 记录本次任务状态、开始/结束时间、数据库总数、成功写入数、失败数量和错误摘要。
8. 新索引稳定运行并超过回滚观察窗口后，再清理旧物理索引。

临时索引建议使用带任务标识的版本名，例如 `sys_dept_org_build_<timestamp>`。时间戳只用于临时索引命名，不作为业务文档 ID。

### 7.3 失败恢复

- **建索引或写入失败：** 不切换别名，旧索引继续服务；清理本次临时索引（清理失败时记录告警），返回失败。
- **数量校验失败：** 不切换别名，保留旧索引，返回预期数量和实际数量差异。
- **别名切换失败：** 保持旧索引服务，记录 ES 返回的错误信息。
- **切换后发现数据异常：** 若旧索引仍保留，执行反向别名切换回旧索引。
- **任务重复触发：** 互斥锁生效时拒绝并发任务，返回“同步任务正在执行”，不启动第二个全量构建。
- **进程中断：** 线上别名仍指向旧索引；下次任务可清理超过保留时间且未被别名引用的临时索引。

### 7.4 响应示例

成功：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "success": true,
    "total": 12000,
    "indexed": 12000,
    "failed": 0,
    "indexName": "sys_dept_org_v2",
    "message": "组织数据全量同步成功"
  }
}
```

失败时使用项目现有错误响应约定，并在服务端日志记录异常详情；不得把连接凭证或敏感配置写入响应。

## 8. 空值规范

1. 所有可空单值字段统一返回 JSON `null`。
2. 无数据的集合统一返回空数组 `[]`，不返回 `null`。
3. 不用空字符串 `""` 或字符串 `"null"` 表示空值。
4. 字段本身属于必需标识且缺失时，应记录数据质量日志；不得伪造 ID 或机构关系。
5. 坐标缺失时 `lng`、`lat` 返回 `null`，不参与地理计算。

## 9. 代码落点建议

实际包名和现有 service/mapper 结构以仓库代码为准，建议按以下职责实现：

- Controller：在 `SysDeptController` 中增加组织树查询入口；ES 同步入口可放在同一控制器，也可拆到独立的管理控制器。若拆分，需统一权限和路由规范。
- Service：组织树查询服务负责参数分流、权限范围、ES 查询和路径组装；同步服务负责锁、索引构建、批量写入、校验、别名切换和旧索引清理。
- Mapper：提供应用 `@DataScope` 的可见组织 ID 查询，以及全量读取组织记录的方法。
- Entity/DTO：适配新增数据库字段，并建立明确的组织树响应 DTO，避免直接暴露 ES 内部字段 `ancestor_ids`。
- ES client：复用项目已配置的 ES 客户端及连接配置；实施前确认 ES 主版本和当前 Java client，避免引入与现有集群不兼容的新客户端。
- 日志：记录同步任务 ID、耗时、数量、失败原因；不得记录敏感连接配置。

## 11. 验收测试

### 组织树查询

- [ ] 无参数请求只返回浙江省根节点。
- [ ] 指定 `parentId` 只返回直接下级，不返回孙级节点。
- [ ] 名称搜索返回命中节点和所有上级，不返回命中节点的下级。
- [ ] 多个命中节点共享祖先时，祖先不重复，结果顺序稳定。
- [ ] 越权组织不会通过懒加载、搜索或祖先路径还原泄露。
- [ ] 缺失可选字段返回 `null`，空集合返回 `[]`。
- [ ] 不存在的 `parentId` 返回空数组或项目约定的参数错误，不触发全量查询。

### ES 同步

- [ ] 全量同步后 ES 文档数与数据库应同步记录数一致。
- [ ] 相同 `dept_id` 不产生重复文档。
- [ ] 数据库已删除的组织不会残留在新索引中。
- [ ] Bulk 任一批次失败时不切换别名。
- [ ] 校验失败时旧索引仍可查询。
- [ ] 成功后查询别名指向新索引；回滚时能切回旧索引。
- [ ] 并发触发同步时只有一个任务执行。
- [ ] 无同步权限的账号无法触发全量同步。

### 现有接口

## 12. 风险与说明

1. ES 版本及客户端尚需实施前核验；本文 mapping 和别名操作描述的是设计要求，不代表已经在目标集群验证过具体 API 兼容性。
2. `@DataScope` 目前生成 SQL 过滤条件，ES 本身不会执行该条件；必须通过数据库权限 ID 查询或等价方案将数据范围转换成 ES filter。
3. 第三方历史字段和经纬度未提供前，字段可能为空；本系统不猜测机构类型、父级第三方编号或坐标。
4. 全量索引切换需要预留新旧索引并存的磁盘空间；执行前应检查 ES 磁盘水位及索引保留策略。
5. 全量同步接口属于高权限操作，应记录审计日志并限制调用频率。

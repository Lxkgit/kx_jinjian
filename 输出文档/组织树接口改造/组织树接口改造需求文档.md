# 组织树接口改造需求文档

## 1. 文档说明

- **项目：** kx_jinjian
- **需求主题：** 组织树查询性能优化与接口改造
- **文档状态：** 需求文档初稿，供评审确认
- **本次范围：** 仅调整 `SysDeptController` 中四个基础组织管理接口（查询列表、新增、修改、删除），并新增组织树查询和 ES 手动同步接口；其他既有接口不在本次改造范围内。

本文用于明确业务需求、接口契约和验收标准。接口沿用现有 `SysDeptController` 的 `/dept` 路径前缀及 `AjaxResult` 响应封装。

## 2. 需求背景

当前部门管理页面和组织树查询存在两类性能问题：

1. 组织查询接口加载耗时约 1.67 秒，需要优化服务端查询效率。
2. 组织数据量较大，一次性返回大量节点会增加网络传输量和前端渲染压力，影响页面交互响应。

本次决定继续使用 Elasticsearch（ES），同时引入组织树懒加载。ES 和懒加载分别解决查询速度和一次性加载数据量问题，两者同时保留。

## 3. 需求目标

1. 继续使用 ES 查询组织树数据，优化组织查询接口响应速度。
2. 使用懒加载机制，避免首次请求加载完整组织树。
3. 固定以“浙江省”为组织树根节点。
4. 沿用系统现有组织关系字段维护树结构，不使用第三方机构编号推导父子关系。
5. 组织树支持按机构名称搜索，搜索结果包含从根节点到命中机构的全部上级组织。
6. 每个组织树节点返回约定的全部展示字段。
7. 提供手动同步接口，将数据库中的全部组织机构数据同步更新至 ES。
8. 组织树查询沿用项目现有 `@DataScope` 数据范围机制。

## 4. 组织树结构与层级规则

### 4.1 根节点

组织树根节点固定为“浙江省”，不根据当前账号或角色切换根节点。

### 4.2 系统内部组织关系

组织树的父子关系继续使用现有字段：

- `dept_id`：系统内部组织主键。
- `parent_id`：父部门 ID。
- `ancestors`：祖级路径。

组织树查询、懒加载下级查询、搜索结果上级路径还原，均应以系统内部组织关系为依据。

### 4.3 监管机构与银行机构

组织层级按照数据库中维护的实际机构关系组织。监管机构之间的层级按监管机构数据及实际父子关系确定，不通过服务业务规则推断。银行及其总行、分行、支行按实际机构关系维护，不要求所有银行节点机械套用省、市、区行政层级。

参考结构：

```text
浙江省
├── 浙江省金融监管局
│   └── 杭州市金融监管分局
│       └── 萧山区金融监管支局
├── xx银行
│   └── xxx分行
│       └── xxx支行
└── xx银行
```

## 5. 机构字段要求

每个组织树节点均应返回以下全部字段，不采用“树节点精简字段、展开详情再查完整字段”的方案：

| 展示字段 | 数据字段或处理方式 | 要求 |
|---|---|---|
| 机构名称 | `dept_name` | 返回机构名称 |
| 机构号 | `org_num` | 第三方系统对接机构编号，仅记录，不用于树层级计算 |
| 机构地址 | `address` | 返回机构地址 |
| 机构负责人 | `duty_name` | 返回负责人姓名 |
| 负责人固定电话 | `duty_telephone` | 返回固定电话 |
| 负责人移动电话 | `duty_phone` | 返回移动电话 |
| 机构经纬度 | `lng`、`lat` | 返回数据库中已有的经纬度；当前暂时缺少可用经纬度数据 |
| 所属网格 | 后续依据经纬度进行落格计算 | 当前因缺少经纬度，暂时无法完成落格；不得直接假定 `area_code` 就是网格编码 |
| 上级机构 | 使用 `parent_id` 关联上级机构，必要时参考 `ancestors` | 按系统内部组织关系返回 |
| 机构类型 | 新增 `org_type` | 区分省/市/区/总/分/支 |
| 机构介绍 | 新增 `org_introduction` | 返回机构介绍 |

字段暂无数据时，仍返回约定字段：可空的单值字段统一使用 JSON `null`，不得使用空字符串或字符串 `"null"` 表示空值；集合无数据时返回空数组 `[]`。不得因单个字段为空导致整条组织节点查询失败。

## 6. 数据库字段调整

确认新增以下字段：

| 字段 | 建议类型 | 注释 | 用途 |
|---|---|---|---|
| `org_type` | `varchar(20)` | 机构类型：省/市/区/总/分/支 | 表示机构业务类型 |
| `org_introduction` | `text` | 机构介绍 | 保存机构介绍 |
| `parent_org_num` | `varchar(100)` | 上级机构第三方机构编号 | 记录上级机构的第三方对接编号 |

建议 SQL（正式执行前应核对现有表结构及字段是否已存在）：

```sql
ALTER TABLE `sys_dept`
    ADD COLUMN `org_type` varchar(20) DEFAULT NULL COMMENT '机构类型：省/市/区/总/分/支',
    ADD COLUMN `org_introduction` text COMMENT '机构介绍',
    ADD COLUMN `parent_org_num` varchar(100) DEFAULT NULL COMMENT '上级机构第三方机构编号';
```

### 6.1 第三方机构编号说明

- `org_num`：本机构的第三方机构编号。
- `parent_org_num`：上级机构的第三方机构编号。
- 两个字段仅用于第三方系统对接和信息记录。
- 两个字段不参与本系统组织树父子关系计算，不替代 `parent_id`，不影响现有组织树功能。
- 组织树内部层级仍以 `dept_id`、`parent_id`、`ancestors` 为准。

## 7. 接口改造范围

### 7.1 现有接口

本次只调整 `SysDeptController` 中以下四个基础组织管理接口：

1. `GET /dept/list`：查询部门列表。
2. `POST /dept`：新增部门。
3. `PUT /dept`：修改部门。
4. `DELETE /dept/{deptId}`：删除部门。

以上路径已按当前仓库 `SysDeptController` 的实际映射核对。`/dept/list/exclude/{deptId}`、`/dept/selectDeptTree`、`/dept/pilotCenterPart/networkList` 等其他既有接口本次不改；新增组织树查询和 ES 手动同步接口单独处理。

### 7.2 新增接口一：根据账号角色查询当前组织权限内的组织树

**目标：** 新增组织树查询接口，供前端获取组织结构，并为后续“责任网点多分配”场景预留扩展空间。

需求要求：

- 根节点固定为浙江省。
- 组织数据从 ES 查询。
- 支持懒加载，能够按指定组织节点查询其直接下级组织。
- 支持按机构名称搜索。
- 搜索命中后返回命中机构及其全部上级组织，保证前端可以还原从浙江省到命中机构的完整路径。
- 每个节点返回第 5 节约定的全部字段。
- 组织树查询沿用项目现有 `@DataScope` 数据范围机制；固定浙江省根节点，懒加载和名称搜索均须遵守当前用户的数据范围。
- 为后续责任网点多分配预留扩展能力，但本次不实现额外的责任网点分配规则。

#### 接口契约

- **URL：** `GET /dept/tree`（遵循现有控制器 `@RequestMapping("/dept")` 路径前缀）。
- **参数：**
  - `parentId`：可选，组织节点 ID。未传且未传 `keyword` 时返回固定根节点浙江省；传入时返回该节点的直接下级节点。
  - `keyword`：可选，机构名称关键字。非空时执行名称搜索，返回命中节点及其全部上级节点，不返回命中节点的下级节点。搜索模式下忽略 `parentId`。
- **权限：** 沿用 `@DataScope`。由于组织树检索使用 ES，实施时必须将当前用户的数据范围实际应用于 ES 命中结果，不能只添加注解而不执行过滤。根节点固定为浙江省。
- **响应：** 沿用 `AjaxResult` 封装，`data` 为组织节点数组；每个节点包含本需求约定的完整字段以及 `deptId`、`parentId`、`ancestors`。不新增 `hasChildren` 等子节点标识字段，前端使用 `deptId` 与 `ancestors` 判断节点关系。
- **示例：**

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": [
    {
      "deptId": 100,
      "parentId": 0,
      "ancestors": "0",
      "deptName": "浙江省",
      "orgNum": null,
      "address": null,
      "dutyName": null,
      "dutyTelephone": null,
      "dutyPhone": null,
      "lng": null,
      "lat": null,
      "orgType": null,
      "orgIntroduction": null,
      "parentOrgNum": null
    }
  ]
}
```

以上示例用于明确响应形状，ID 和具体根节点数据以数据库实际记录为准。

### 7.3 新增接口二：手动同步组织树数据至 ES

**目标：** 提供手动触发的组织机构数据同步接口。

需求要求：

1. 从数据库读取全部组织机构数据。
2. 将数据库组织数据同步更新到 ES 中的组织树索引。
3. ES 中的组织数据字段暂时以数据库字段为准，包含新增字段 `org_type`、`org_introduction`、`parent_org_num`。
4. 同步完成后应能明确反馈成功或失败，具体响应格式按项目统一接口规范设计。
5. 同步过程不得将 `org_num` 或 `parent_org_num` 用作组织树父子关系的计算依据。

#### 接口契约

- **URL：** `POST /dept/es/sync`。
- **参数：** 无请求参数；从数据库读取全部组织机构数据。
- **权限：** 作为会修改 ES 索引数据的运维操作，应沿用项目权限体系配置明确的操作权限，不向普通组织查询权限自动开放。
- **同步策略：** 全量覆盖。每次读取数据库全量组织数据，构建新的完整索引；校验写入数量及构建结果后，通过别名原子切换生效。旧索引在切换成功前保留，避免构建失败导致线上索引不可用。
- **失败恢复：** 构建或校验失败时不切换别名，删除本次未生效的临时索引并保留当前生效索引；切换后若发现异常，可将别名切回上一版索引。同步结果记录成功/失败、读取数量、写入数量和错误信息。
- **响应：** 沿用 `AjaxResult` 封装，`data` 返回本次同步摘要，例如 `success`、`total`、`indexed`、`indexName` 和 `message`。

## 8. 懒加载与名称搜索

### 8.1 懒加载

- 初次请求只加载浙江省根节点及前端首屏所需的必要层级，不一次性加载整棵树。
- 展开节点时，根据该节点的系统内部组织 ID 查询其直接下级节点。
- 每次展开请求只返回该节点的直接下级，不返回所有层级的完整子树。
- 节点数据仍需包含第 5 节列出的全部展示字段。
- 不新增专门的子节点标识字段；本次文档不涉及前端改造，前端按现有 `deptId` 和 `ancestors` 判断节点关系。

### 8.2 机构名称搜索

- 支持按机构名称进行搜索。
- 搜索结果必须包含命中机构及其全部上级组织。
- 返回的上级路径必须能够连接至固定根节点“浙江省”。
- 搜索结果用于前端定位并展示完整组织路径。
- 搜索只返回命中节点及其全部上级节点，不返回命中节点的下级节点。
- 搜索结果及其上级路径应返回完整展示字段。

## 9. ES 索引与数据同步设计

### 9.1 索引与文档标识

- **物理索引命名：** `sys_dept_org_v1`，后续版本按版本号递增。
- **查询别名：** `sys_dept_org`。业务查询只访问别名，不直接绑定某个物理索引。
- **文档唯一标识：** 使用数据库 `dept_id` 作为 ES 文档 `_id`，保证同一机构全量同步时不会产生重复文档。
- **数据来源：** MySQL 是组织机构主数据来源，ES 是搜索与组织树检索索引；ES 不反向修改数据库。

### 9.2 字段映射建议

| 字段 | ES 类型 | 用途 |
|---|---|---|
| `dept_id` | `long` | 文档业务 ID，与 `_id` 一致 |
| `parent_id` | `long` | 查询直接下级节点 |
| `ancestors` | `keyword` | 保留数据库祖级路径原值 |
| `ancestor_ids` | `long` 数组 | 按祖先 ID 检索及还原上级路径 |
| `dept_name` | `text`，附带 `keyword` 子字段 | 机构名称全文/关键字搜索及精确排序 |
| `org_num`、`parent_org_num` | `keyword` | 第三方对接编号，仅用于查询/展示，不用于组织层级计算 |
| `address`、`duty_name`、`duty_telephone`、`duty_phone` | `keyword` 或按搜索需求配置 `text` | 机构展示信息 |
| `org_type` | `keyword` | 机构类型筛选 |
| `org_introduction` | `text` | 机构介绍检索/展示 |
| `lng`、`lat` | `double` | 经纬度数值；无有效值时存 JSON `null` 或不写入字段 |
| `status`、`del_flag` | `keyword` | 按数据库现有字段映射，用于排除不可见或已删除数据 |

实现时应按当前 ES 版本支持的 mapping 语法创建索引，并核对实际数据库字段是否存在；不将 `area_code` 当作网格编码。

### 9.3 查询方式

- 懒加载：使用 `parent_id` 精确匹配查询直接子节点，并按现有排序规则返回。
- 名称搜索：对 `dept_name` 执行名称匹配；获取命中机构后，依据 `ancestor_ids` 查询其上级机构并按祖先顺序组装路径。只返回命中机构及其全部上级，不返回下级节点。
- 根节点：从固定的浙江省组织记录确定根节点，不通过第三方编号推导。
- 权限：先依据现有 `@DataScope` 规则确定用户可见的数据范围，并在 ES 搜索和路径组装时执行实际过滤；不能仅依赖注解而忽略 ES 查询中的权限约束。

### 9.4 全量覆盖及失败恢复

- 手动同步接口每次从数据库读取全部应同步的组织机构数据，写入新建的临时物理索引。
- 写入后执行数量及关键字段校验，校验通过后将 `sys_dept_org` 别名原子切换到新索引。
- 切换前发生异常：保留旧别名指向和线上索引，清理本次临时索引并返回失败信息。
- 切换后验证失败：保留旧索引，在可恢复窗口内将别名切回旧索引；确认新索引稳定后再按保留策略清理旧索引。
- 重复执行使用相同流程，文档以 `dept_id` 为唯一标识，不产生重复数据。

### 9.5 历史数据和空值

- `org_type`、`org_introduction`、`parent_org_num` 的历史数据由第三方提供，本系统不自行推断或批量编造。
- 经度、纬度数据由第三方提供，属于本次组织树查询/ES 索引之外的业务依赖；在缺少有效坐标时不实现完整网格落格逻辑。
- 可空单值字段统一返回 JSON `null`，集合无数据统一返回 `[]`，不使用空字符串或字符串 `"null"` 代表空值。

## 10. 权限范围

角色及数据权限沿用项目现有 `@DataScope` 注解机制，不另行实现一套角色权限过滤逻辑。

- `@DataScope` 定义于 `kx-common-datascope` 模块，作用于方法，可配置部门别名、部门 ID 别名、用户别名、用户 ID 别名及权限字符。
- 现有 `DataScopeAspect` 在方法执行前获取当前登录用户，根据用户角色的数据权限规则生成 SQL 条件，并写入首个 `BaseEntity` 参数的 `params.dataScope`。
- 对应 Mapper SQL 必须引用 `params.dataScope` 条件，数据范围控制才会实际生效；编码前需核对注解位置、SQL 别名和 Mapper 条件。
- 新增组织树查询接口也应复用该机制控制当前用户可见的数据范围；固定根节点仍为浙江省，懒加载和名称搜索不得绕过数据权限限制。
- 新增、修改、删除接口继续保留现有参数校验、上下级关系校验及 `checkDeptDataScope` 等操作级权限校验，不以 `@DataScope` 替代。

## 11. 已明确的外部数据依赖

- 历史数据中的 `org_type`、`org_introduction`、`parent_org_num` 由第三方提供，本系统不负责推断补齐。
- 经度、纬度由第三方提供；经纬度缺失导致的网格落格问题不属于本次业务改造范围，本次不设计坐标补齐流程或网格落格实现。

## 12. 验收标准

### 12.1 组织关系

- [ ] 组织树根节点始终为浙江省。
- [ ] 树节点父子关系使用 `dept_id`、`parent_id`、`ancestors`。
- [ ] 修改 `org_num` 或 `parent_org_num` 不会改变组织树层级。
- [ ] 监管机构和银行机构按数据库维护的实际组织关系展示，不因服务业务规则被错误挂接。

### 12.2 字段返回

- [ ] 每个组织树节点均返回需求约定的全部展示字段。
- [ ] `org_type`、`org_introduction`、`parent_org_num` 已纳入数据库字段和 ES 同步范围。
- [ ] 缺少经纬度时，接口仍可正常返回组织节点；网格落格能力在经纬度数据具备后再验证。

### 12.3 懒加载和搜索

- [ ] 初次加载不会一次性返回完整组织树。
- [ ] 展开节点只查询其直接下级组织。
- [ ] 支持按机构名称搜索。
- [ ] 搜索命中后仅返回命中机构及其全部上级组织，不返回命中机构下级节点，路径可追溯到浙江省根节点。
- [ ] 懒加载和搜索均不依赖第三方机构编号计算组织关系。

### 12.4 ES 同步和接口范围

- [ ] 手动同步接口从数据库读取全部组织机构，全量构建新索引并通过别名切换；失败时保留旧索引可用。
- [ ] ES 中组织字段按数据库字段同步。
- [ ] 本次只调整 `GET /dept/list`、`POST /dept`、`PUT /dept`、`DELETE /dept/{deptId}` 四个基础组织接口，并新增组织树查询和手动同步两个接口。
- [ ] 查询数据范围沿用现有 `@DataScope` 机制，并将可见范围实际应用于 ES 查询；新增、修改、删除保留现有操作级权限校验。
- [ ] 新增接口采用 `GET /dept/tree` 和 `POST /dept/es/sync`，响应沿用 `AjaxResult`。
- [ ] 不新增子节点标识字段；空单值字段返回 JSON `null`，空集合返回 `[]`。

### 12.5 性能目标

- [ ] 通过 ES 查询优化接口响应速度。
- [ ] 通过懒加载降低首次请求的数据量和前端渲染负担。
- [ ] 具体性能验收阈值应在测试前结合现有基线和测试数据规模另行确定；当前不擅自设定未经确认的毫秒级指标。

## 13. 变更边界

本需求文档明确业务范围，但不直接授权扩大改造范围。未经确认，不新增其他现有接口的改造、不改变现有组织关系模型，也不将第三方机构编号用于组织树层级判断；数据权限沿用项目现有 `@DataScope` 机制。

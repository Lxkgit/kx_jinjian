# 组织树接口改造需求文档

## 1. 文档说明

- **项目：** kx_jinjian
- **需求主题：** 组织树查询性能优化与接口改造
- **文档状态：** 需求文档初稿，供评审确认
- **本次范围：** 仅调整本文列出的四个现有接口，并新增两个接口；不在本文范围内的业务功能不做扩展。

本文用于明确业务需求和验收标准。具体接口 URL、请求参数、响应 JSON 结构、ES 索引细节及异常处理方式，需在技术设计阶段结合现有代码进一步确定。

## 2. 需求背景

当前部门管理页面和组织树查询存在两类性能问题：

1. 组织查询接口加载耗时约 1.67 秒，需要优化服务端查询效率。
2. 组织数据量较大，一次性返回大量节点会增加网络传输量和前端渲染压力，影响页面交互响应。

本次决定继续使用 Elasticsearch（ES），同时引入组织树懒加载。ES 和懒加载分别解决查询速度和一次性加载数据量问题，两者同时保留。

## 3. 需求目标

1. 继续使用 ES 查询组织树数据，优化组织查询接口响应速度。
2. 使用懒加载机制，避免首次请求加载完整组织树。
3. 固定以“浙江省”为组织树根节点。
4. 沿用系统现有组织关系字段维护树结构，不使用第三方机构编号推导父子关系。
5. 组织树支持按机构名称搜索，搜索结果包含从根节点到命中机构的全部上级组织。
6. 每个组织树节点返回约定的全部展示字段。
7. 提供手动同步接口，将数据库中的全部组织机构数据同步更新至 ES。
8. 当前阶段暂不实现组织树角色权限过滤。

## 4. 组织树结构与层级规则

### 4.1 根节点

组织树根节点固定为“浙江省”，不根据当前账号或角色切换根节点。

### 4.2 系统内部组织关系

组织树的父子关系继续使用现有字段：

- `dept_id`：系统内部组织主键。
- `parent_id`：父部门 ID。
- `ancestors`：祖级路径。

组织树查询、懒加载下级查询、搜索结果上级路径还原，均应以系统内部组织关系为依据。

### 4.3 监管机构与银行机构

组织层级按照数据库中维护的实际机构关系组织。监管机构之间的层级按监管机构数据及实际父子关系确定，不通过服务业务规则推断。银行及其总行、分行、支行按实际机构关系维护，不要求所有银行节点机械套用省、市、区行政层级。

参考结构：

```text
浙江省
├── 浙江省金融监管局
│   └── 杭州市金融监管分局
│       └── 萧山区金融监管支局
├── xx银行
│   └── xxx分行
│       └── xxx支行
└── xx银行
```

## 5. 机构字段要求

每个组织树节点均应返回以下全部字段，不采用“树节点精简字段、展开详情再查完整字段”的方案：

| 展示字段 | 数据字段或处理方式 | 要求 |
|---|---|---|
| 机构名称 | `dept_name` | 返回机构名称 |
| 机构号 | `org_num` | 第三方系统对接机构编号，仅记录，不用于树层级计算 |
| 机构地址 | `address` | 返回机构地址 |
| 机构负责人 | `duty_name` | 返回负责人姓名 |
| 负责人固定电话 | `duty_telephone` | 返回固定电话 |
| 负责人移动电话 | `duty_phone` | 返回移动电话 |
| 机构经纬度 | `lng`、`lat` | 返回数据库中已有的经纬度；当前暂时缺少可用经纬度数据 |
| 所属网格 | 后续依据经纬度进行落格计算 | 当前因缺少经纬度，暂时无法完成落格；不得直接假定 `area_code` 就是网格编码 |
| 上级机构 | 使用 `parent_id` 关联上级机构，必要时参考 `ancestors` | 按系统内部组织关系返回 |
| 机构类型 | 新增 `org_type` | 区分省/市/区/总/分/支 |
| 机构介绍 | 新增 `org_introduction` | 返回机构介绍 |

字段暂无数据时，按现有项目接口的统一数据约定返回空值或空字段，不应因单个字段为空导致整条组织节点查询失败。具体空值格式在接口设计阶段统一。

## 6. 数据库字段调整

确认新增以下字段：

| 字段 | 建议类型 | 注释 | 用途 |
|---|---|---|---|
| `org_type` | `varchar(20)` | 机构类型：省/市/区/总/分/支 | 表示机构业务类型 |
| `org_introduction` | `text` | 机构介绍 | 保存机构介绍 |
| `parent_org_num` | `varchar(100)` | 上级机构第三方机构编号 | 记录上级机构的第三方对接编号 |

建议 SQL（正式执行前应核对现有表结构及字段是否已存在）：

```sql
ALTER TABLE `sys_dept`
    ADD COLUMN `org_type` varchar(20) DEFAULT NULL COMMENT '机构类型：省/市/区/总/分/支',
    ADD COLUMN `org_introduction` text COMMENT '机构介绍',
    ADD COLUMN `parent_org_num` varchar(100) DEFAULT NULL COMMENT '上级机构第三方机构编号';
```

### 6.1 第三方机构编号说明

- `org_num`：本机构的第三方机构编号。
- `parent_org_num`：上级机构的第三方机构编号。
- 两个字段仅用于第三方系统对接和信息记录。
- 两个字段不参与本系统组织树父子关系计算，不替代 `parent_id`，不影响现有组织树功能。
- 组织树内部层级仍以 `dept_id`、`parent_id`、`ancestors` 为准。

## 7. 接口改造范围

### 7.1 现有接口

本次现阶段只调整以下四个现有接口，实际路径以代码中的控制器映射为准：

1. `GET /dept/list`：部门列表。
2. `GET /dept/list/exclude/{deptId}`：排除指定部门及其子级的部门列表。
3. `GET /dept/selectDeptTree`：组织树查询。
4. `GET /dept/pilotCenterPart/networkList`：支行列表。

以上范围之外的既有接口不纳入本次改造，除非后续另行确认。

### 7.2 新增接口一：根据账号角色查询当前组织权限内的组织树

**目标：** 新增组织树查询接口，供前端获取组织结构，并为后续“责任网点多分配”场景预留扩展空间。

需求要求：

- 根节点固定为浙江省。
- 组织数据从 ES 查询。
- 支持懒加载，能够按指定组织节点查询其直接下级组织。
- 支持按机构名称搜索。
- 搜索命中后返回命中机构及其全部上级组织，保证前端可以还原从浙江省到命中机构的完整路径。
- 每个节点返回第 5 节约定的全部字段。
- 当前阶段暂不实现角色权限过滤；接口名称可体现未来用途，但本次不增加按角色限制数据范围的业务逻辑。
- 为后续责任网点多分配预留扩展能力，但本次不实现额外的责任网点分配规则。

具体 URL、HTTP 方法、参数名、响应结构及是否返回子节点标识，由技术设计阶段结合现有接口风格确定。

### 7.3 新增接口二：手动同步组织树数据至 ES

**目标：** 提供手动触发的组织机构数据同步接口。

需求要求：

1. 从数据库读取全部组织机构数据。
2. 将数据库组织数据同步更新到 ES 中的组织树索引。
3. ES 中的组织数据字段暂时以数据库字段为准，包含新增字段 `org_type`、`org_introduction`、`parent_org_num`。
4. 同步完成后应能明确反馈成功或失败，具体响应格式按项目统一接口规范设计。
5. 同步过程不得将 `org_num` 或 `parent_org_num` 用作组织树父子关系的计算依据。

具体 URL、HTTP 方法、索引名称、全量覆盖策略、重复执行处理方式及失败恢复机制，在技术设计阶段确定。

## 8. 懒加载与名称搜索

### 8.1 懒加载

- 初次请求只加载浙江省根节点及前端首屏所需的必要层级，不一次性加载整棵树。
- 展开节点时，根据该节点的系统内部组织 ID 查询其直接下级节点。
- 每次展开请求只返回该节点的直接下级，不返回所有层级的完整子树。
- 节点数据仍需包含第 5 节列出的全部展示字段。
- 接口需要提供前端判断节点是否存在下级节点所需的信息；具体字段名在接口设计阶段确定。

### 8.2 机构名称搜索

- 支持按机构名称进行搜索。
- 搜索结果必须包含命中机构及其全部上级组织。
- 返回的上级路径必须能够连接至固定根节点“浙江省”。
- 搜索结果用于前端定位并展示完整组织路径。
- 是否同时返回命中节点的下级节点，本需求暂不强制，需在接口设计阶段结合前端交互确定。
- 搜索结果及其上级路径应返回完整展示字段。

## 9. ES 数据同步要求

- ES 作为组织树查询的数据检索来源，数据库作为组织机构数据的来源。
- 手动同步接口应读取数据库全部组织机构数据并更新 ES。
- ES 字段暂时按数据库字段同步，数据库新增字段也应纳入同步数据。
- ES 的索引映射、唯一文档标识、全量重建或覆盖策略、同步失败处理及历史数据补齐方式属于技术设计内容，实施前需明确。
- ES 中的父子关系字段应保留系统内部组织关系所需的数据，确保能够根据 `dept_id`、`parent_id`、`ancestors` 查询子节点及还原搜索结果的完整上级路径。

## 10. 权限范围

本次暂不实现组织树的角色权限过滤。

- 不在本次实现多角色账号、特殊角色、无权限角色的数据范围判断。
- 新增接口当前返回浙江省根节点下的组织结构，后续如需增加角色权限过滤，应另行明确权限规则。
- “根据账号角色查询当前组织权限”作为接口的预留业务方向，不代表本次已经实现权限控制。

## 11. 暂缓事项与技术设计待定项

以下内容不阻塞当前业务需求范围，但应在技术设计或实施前确定：

1. 两个新增接口的最终 URL、HTTP 方法、参数及响应格式。
2. ES 索引名称、字段映射、文档唯一标识及查询方式。
3. 手动同步采用全量覆盖还是其他更新策略，以及失败恢复机制。
4. 历史数据的 `org_type`、`org_introduction`、`parent_org_num` 如何补齐。
5. 当前缺少经纬度数据，网格落格暂时无法完整实现；经纬度数据来源及后续补齐方式待定。
6. 机构名称搜索是否同时返回命中节点的下级节点。
7. 前端用于判断是否存在下级节点的响应字段。
8. 接口字段空值的统一格式。

## 12. 验收标准

### 12.1 组织关系

- [ ] 组织树根节点始终为浙江省。
- [ ] 树节点父子关系使用 `dept_id`、`parent_id`、`ancestors`。
- [ ] 修改 `org_num` 或 `parent_org_num` 不会改变组织树层级。
- [ ] 监管机构和银行机构按数据库维护的实际组织关系展示，不因服务业务规则被错误挂接。

### 12.2 字段返回

- [ ] 每个组织树节点均返回需求约定的全部展示字段。
- [ ] `org_type`、`org_introduction`、`parent_org_num` 已纳入数据库字段和 ES 同步范围。
- [ ] 缺少经纬度时，接口仍可正常返回组织节点；网格落格能力在经纬度数据具备后再验证。

### 12.3 懒加载和搜索

- [ ] 初次加载不会一次性返回完整组织树。
- [ ] 展开节点只查询其直接下级组织。
- [ ] 支持按机构名称搜索。
- [ ] 搜索命中后返回命中机构及其全部上级组织，路径可追溯到浙江省根节点。
- [ ] 懒加载和搜索均不依赖第三方机构编号计算组织关系。

### 12.4 ES 同步和接口范围

- [ ] 手动同步接口从数据库读取全部组织机构并更新 ES。
- [ ] ES 中组织字段按数据库字段同步。
- [ ] 本次只调整约定的四个现有接口，并新增组织树查询和手动同步两个接口。
- [ ] 本次不实现角色权限过滤。

### 12.5 性能目标

- [ ] 通过 ES 查询优化接口响应速度。
- [ ] 通过懒加载降低首次请求的数据量和前端渲染负担。
- [ ] 具体性能验收阈值应在测试前结合现有基线和测试数据规模另行确定；当前不擅自设定未经确认的毫秒级指标。

## 13. 变更边界

本需求文档明确业务范围，但不直接授权扩大改造范围。未经确认，不新增其他现有接口的改造、不改变现有组织关系模型、不实现角色权限过滤，也不将第三方机构编号用于组织树层级判断。

# 金监防非打非系统改造高层需求文档

## 1. 文档说明

- **项目：** 浙江省金监局防非打非网格系统
- **文档定位：** 高层业务需求，只描述"做什么"与业务规则，不涉及技术实现（表结构、接口、代码等实现细节见《金监防非打非系统改造需求分析文档》及其他系列文档）。
- **状态：** 需求已确认稿（确认日期 2026-10-22）

## 2. 背景与目标

**现状问题：**

1. 系统中存在"网点管理"菜单（银行网点列表），但其使用场景不明确，与机构管理职责重叠，需要统一处置口径。
2. 机构（部门）管理页面一次性加载全部机构节点，机构数量大时加载与响应缓慢。
3. 机构档案信息不完整，缺少机构类型、机构层级、机构介绍、所属网格、管辖区等关键属性，无法支撑按机构类型与辖区开展业务。
4. 金监局缺少按"管辖区"统一查看辖内网格、银行、扫楼清街、线索上报数据的口径。
5. 网格分配规则不明确：金监局与银行的网格归属方式应不同；且一个网格只能归属一家责任银行，不能满足实际工作需要。
6. 工程存量代码缺乏定期整理，存在无关、无效及与现行业务冲突的代码，维护成本高、变更风险大。

**改造目标：**

1. 明确网点管理的处置方式，升级机构管理（懒加载 + 档案字段扩展）。
2. 金监局按管辖区编码查看辖内业务数据。
3. 明确网格分配规则：金监局按管辖区自动归属、银行按需分配。
4. 网格支持分配给多家责任银行。
5. 对存量代码开展整理，经人工判断后移除无关、无效、冲突代码。

## 3. 术语与业务口径

| 术语 | 口径 |
|---|---|
| 金监局 | 金融监管机构（省局/分局/支局），在系统中是一种机构类型 |
| 银行机构 | 各银行及其总行/分行/支行，在系统中是一种机构类型 |
| 网格 | 防非打非工作的最小管理单元，每个网格有唯一网格编码 |
| 管辖区编码 | 行政区划编码，支持省级 2 位（如 `33`）、市级 4 位（如 `3303`）、区县级 6 位（如 `330301`，温州鹿城区）；通过编码前缀确定管辖范围 |
| 责任银行 | 被分配到网格、承担该网格防非打非工作任务的银行机构 |
| 所属网格 | 机构按自身经纬度定位落入的网格，由系统自动计算得出 |

## 4. 需求一：网点管理处置与机构管理升级

### 4.1 网点管理菜单下线保留

1. 网点数据**不合并**入机构管理，原有网点数据、功能原样保留。
2. "网点管理"菜单整体下线，系统中不再提供该功能入口；后续如需恢复，可重新启用菜单。
3. 其他页面（如大屏）正在使用的网点详情能力不受影响，继续可用。
4. 系统内所有涉及机构（金监局、银行）的查询、分配、统计，一律以机构管理中的机构为准。

### 4.2 机构管理懒加载

机构管理页面不再一次性加载全部机构节点：首次进入只加载最上层机构，用户展开某节点时才加载其直接下级，逐层展开。

### 4.3 机构档案字段扩展

机构管理需维护以下档案信息：

| 信息项 | 填写规则 |
|---|---|
| 机构名称 | 必填，支持最长 200 字（银行网点全称） |
| 机构号 | 必填，业务机构编号（非系统内部编码），仅用于对接与展示 |
| 上级机构 | 必填，按机构树选择 |
| 机构类型 | 必填：金监局 / 银行 |
| 机构层级 | 金监局：省/市/区；银行：总行/分行/支行（网点） |
| 机构地址 | 选填 |
| 机构负责人 | 选填 |
| 负责人固定电话 | 选填 |
| 负责人移动电话 | 选填 |
| 机构介绍 | 选填 |
| 机构经纬度 | 银行机构必填，用于网格定位 |
| 所属网格 | 不允许手填，由系统根据机构经纬度自动计算 |
| 管辖区编码 | 金监局必填、银行机构不可填写；按省/市/区三级选择 |

经纬度缺失或不在任何网格范围内时，所属网格为空，系统提示补录，不允许产生虚假网格归属。

### 4.4 机构查询统一口径

系统内所有机构维度的查询与统计（含辖区查看、网格分配）均以机构管理数据为准，不再以网点档案作为机构来源。

## 5. 需求二：金监局按管辖区编码查看辖内数据

1. 金监局机构设置管辖区编码后，登录系统即可查看辖区内的业务数据：
   - **网格**：网格编码属于本辖区的网格；
   - **银行**：位于本辖区网格内的银行机构；
   - **扫楼清街管理**：本辖区的扫楼清街上报数据与报表；
   - **线索上报管理**：本辖区的线索上报数据与报表。
2. 管辖范围按编码前缀判定：如区县级金监局管辖区编码为 `330301`，则网格编码以 `330301` 开头的网格及其中的银行归其管辖；市级局编码为 `3303` 即自然覆盖下辖各区县。
3. 银行机构的可见数据范围不因本规则改变，仍按原有权限控制。

## 6. 需求三：网格分配规则

1. **金监局不需要分配网格**：其可见网格由管辖区编码自动判定归属，系统为其标注"按管辖区自动归属"，不提供网格分配操作。
2. **银行机构需要分配网格**：银行机构通过网格分配功能获得网格，仅可查看分配给本机构的网格。

## 7. 需求四：网格支持多家责任银行

1. 现状：一个网格最多只能归属一家责任银行。
2. 目标：一个网格允许分配给**多家银行机构**，分配的银行均为责任银行，不区分责任/参与角色。
3. 网格列表、网格详情、大屏展示、台账评分等涉及责任银行的功能，均需支持展示与处理一家网格对应多家银行的情形。

## 8. 需求五：存量代码整理

1. 对当前工程代码开展全面梳理，标注以下三类代码：
   - **无关代码**：与现有业务无关、无人使用的代码；
   - **无效代码**：已无调用方、不再执行的代码（含页面、接口、定时任务等）；
   - **冲突代码**：与本次改造及现行业务规则相冲突、需要移除或调整的代码。
2. 标注结果形成清单，提交**人工评审判断；未经人工确认不得移除**。
3. 经确认移除的代码须可回溯（保留移除记录，必要时可从版本历史恢复）；涉及数据表、对外接口的清理需单独评估。
4. 已明确保留的能力（如大屏网点详情）不在清理范围；清理不得影响在用功能。

## 9. 范围边界（本次不做）

1. 不做网点数据向机构管理的合并迁移。
2. 外部监管网点参照数据（全量银行网点信息）维持现状，仅作大屏参照。
3. 管辖区编码暂不支持街道级。
4. 网格-银行关系不区分责任/参与角色（字段层面预留扩展）。
5. 历史遗留的旧网点表清理另案处理。

## 10. 验收要点

**需求一**
- [ ] 网点管理菜单下线且无其他入口；网点数据与功能保留完整，大屏网点详情正常。
- [ ] 机构管理首屏不再全量加载，逐层展开正常。
- [ ] 机构档案各信息项可维护；机构类型与管辖区编码/所属网格的填写规则正确联动。
- [ ] 系统内机构查询、分配、统计口径统一。

**需求二**
- [ ] 金监局登录后仅可见辖区内的网格、银行、扫楼清街、线索上报数据。
- [ ] 市级局（4 位编码）可查看下辖各区县数据。
- [ ] 银行机构数据范围与改造前一致。

**需求三**
- [ ] 金监局无网格分配入口，其网格按管辖区自动归属且展示正确。
- [ ] 银行机构须通过分配获得网格。

**需求四**
- [ ] 一个网格可分配多家责任银行，重复分配被拦截。
- [ ] 网格列表、详情、大屏、台账均能正确展示一家网格对应多家银行。

**需求五**
- [ ] 形成存量代码标注清单（无关/无效/冲突三类），附人工评审与确认记录。
- [ ] 经确认的代码完成移除，移除过程可回溯。
- [ ] 清理后在用功能回归正常（重点验证大屏网点详情等保留能力）。
